# SwinlineMine — алмазная руда из Minecraft на сайт SWINLINE

Плагин для Paper 26.3 (Java 21+, на сервере Java 25), который связывает
Minecraft-сервер с сайтом SWINLINE. Игрок привязывает Minecraft-ник к аккаунту
сайта, заносит алмазную руду и получает **АР** — отдельную валюту шахты
(**1 алмазная руда = 1 АР**). На АР можно играть в «Алмазной жиле», обменивать
их на SV₽ и выводить обратно в инвентарь (1 АР = 1 руда).

```

┌──────────────────────┐   service key   ┌──────────────────────────┐   ┌────────────────────┐
```

Сайт — единственный источник правды по руде. Плагин не пишет в таблицы напрямую:
он вызывает сервисные RPC `mc_plugin_*`, которые недоступны клиентскому ключу.
Клиент сайта вообще не может записать руду — только прочитать свои строки (RLS).

## Что происходит по шагам

1. **Привязка.** На сайте «Шахта» → «Получить код» → 6 символов на 10 минут.
   В игре: `/sw link ABC123`. Плагин вызывает `mc_plugin_link`, который проверяет
   код и привязывает Minecraft UUID к `auth.uid()` игрока.
2. **Занос.** `/sw deposit 10` (или `all`) снимает 10 блоков `DIAMOND_ORE` из
   инвентаря и вызывает `mc_plugin_deposit(uuid, 10, nonce)`. На сайт
   зачисляется **10 АР** (1 руда = 1 АР). Nonce хранится в
   `pending.yml`, поэтому обрыв сети/рестарт не зачислит руду дважды.
3. **Игра.** На сайте: «Начать спуск» → `mc_dig_start`, «Копать глубже» →
   `mc_dig_step`, «Забрать» → `mc_dig_cashout`. Ставка и выплата — в АР.
4. **Обмен.** `mc_convert` (АР → SV₽) и `mc_buy_ore` (SV₽ → АР).
5. **Вывод.** Сайт: `mc_withdraw_ore` списывает АР и создаёт заявку.
   Плагин при входе/раз в `poll-seconds` вызывает `mc_plugin_sync`, забирает
   заявку через `mc_plugin_withdraw_claim` и выдаёт блоки: **1 АР = 1 алмазная
   руда**. Если места в инвентаре нет — заявка остаётся pending и повторится позже.

## Установка

1. Собери jar (нужен JDK 21+; на сервере Java 25):
   ```bash
   cd minecraft-plugin
   JAVA_HOME="/path/to/jdk-21+" bash build.sh   # скачает Spigot API 26.3 и Gson
   # или: mvn package
   ```
   На Windows локально: `JAVA_HOME="C:/Program Files/Eclipse Adoptium/jdk-25.0.2.10-hotspot" bash build.sh`.
   Готовый файл: `minecraft-plugin/build/SwinlineMine.jar`. Рядом с исходниками
   уже лежит собранный под Paper 26.3 `minecraft-plugin/SwinlineMine.jar` —
   можно взять его, если не менял код.
2. Положи его в `plugins/` на сервере и один раз запусти сервер.
3. Открой `plugins/SwinlineMine/config.yml`:
   ```yaml
   supabase-url: "https://<project-ref>.supabase.co"
   service-key: "<service_role key>"
   ore-material: DIAMOND_ORE
   poll-seconds: 15
   auto-deliver: true
   ```
   `service-key` — **service_role** из Supabase → Project Settings → API.
   Это полный доступ к базе: не публикуй файл и не давай его игрокам.
4. Перезапусти сервер. В консоли должно быть `SwinlineMine включён`.
5. Проверь связь: `/sw ping` (можно из консоли). Ожидаемо: «Сайт на связи».

## Команды

| Команда | Что делает |
|---|---|
| `/sw link <код>` | Привязать Minecraft-ник к аккаунту сайта (код с сайта) |
| `/sw deposit <кол-во\|all>` | Занести алмазную руду на сайт |
| `/sw balance` | Показать руду на сайте и число готовых выводов |
| `/sw withdraw` | Забрать готовые выводы в инвентарь |
| `/sw ping` | Проверить связь с Supabase |

Алиасы: `/swinline`, `/shahta`. Право `swinline.use` (по умолчанию у всех).

## Сайт

Раздел 16 SQL уже применён к живому проекту 26.10.2026 (см. `swinline-docs/minecraft.md`).
Если проект пересоздаётся с нуля — примени раздел заново (личный Management API
токен, не service-role):
   ```bash
   SUPABASE_ACCESS_TOKEN=sbp_... node scripts/apply_mc_sql.mjs
   ```
   Скрипт берёт из `scripts/supabase_security_setup.sql` только раздел «16. ШАХТА»
   и отправляет его через Management API. В конце стоит `NOTIFY pgrst, 'reload schema'`.
   Без токена: `node scripts/apply_mc_sql.mjs --write mc_migration.sql` и применить
   файл в SQL Editor вручную.
2. Адрес сервера в интерфейсе (необязательно): добавь GitHub Secret
   `VITE_MC_SERVER` (например, `play.swinline.fun`) и запушь `main`.
3. Открой на сайте «Шахта». Раздел 16 уже применён к живому проекту; если база
   пересоздана и SQL не применён, страница покажет заглушку «Шахта скоро
   откроется» — примени раздел 16 и обнови страницу.

## Экономика

Значения по умолчанию лежат в `public.mc_config` (одна строка):

| Параметр | Значение | Смысл |
|---|---|---|
| занос/вывод | 1:1 | 1 алмазная руда = 1 АР, без комиссии |
| `ore_to_sv` | 250 | 1 АР → 250 SV₽ |
| `sv_to_ore` | 300 | 1 АР ← 300 SV₽ (спред 20%) |
| `min_withdraw` | 5 | минимум АР на вывод |
| `dig_bust` | 0.18 | шанс обвала на каждом шаге |
| `dig_rtp` | 0.9758 | целевой возврат игры |
| `dig_max_depth` | 30 | максимум шагов |

Множитель считается как `dig_rtp / (1 - dig_bust)^глубина`. Поэтому возврат
одинаков на любой глубине (~97.6%), а не тает с каждым шагом. Менять без
пересборки:

```sql
UPDATE public.mc_config
SET ore_to_sv = 250, sv_to_ore = 300, min_withdraw = 5,
    dig_bust = 0.18, dig_rtp = 0.9758, dig_max_depth = 30
WHERE id;
```

Важно: АР — это отдельная валюта, привязанная к предмету 1:1. Если на сервере
есть плагины/моды, которые бесплатно выдают `DIAMOND_ORE`, их «добыча»
автоматически становится АР на сайте. Настрой экономику сервера так, чтобы руда
чего-то стоила.

## Безопасность и устойчивость

- **service-key** лежит в `config.yml`. Он даёт полный доступ к базе. Держи
  сервер доверенным, закрой файл правами ОС, при утечке — ротируй ключ в
  Supabase и обнови конфиг.
- **Коды привязки**: 6 символов из 32-буквенного алфавита, живут 10 минут,
  одноразовые; плагин не чаще одной попытки в 3 секунды на игрока.
- **Занос идемпотентен**: nonce + `pg_advisory_xact_lock`; повтор после обрыва
  сети возвращает `duplicate: true` и не зачисляет руду второй раз.
- **Вывод атомарен**: `mc_plugin_withdraw_claim` под `FOR UPDATE` переводит
  заявку `pending → delivered`; повторная выдача вернёт `ok: false`.
  Окно между «заявка выдана» и «предметы в инвентаре» крошечное; при падении
  сервера ровно в этот момент руда может потеряться — компенсируй вручную:
  ```sql
  -- посмотреть заявку
  SELECT * FROM public.mc_withdrawals WHERE status = 'delivered' ORDER BY delivered_at DESC LIMIT 5;
  ```
- **Клиент не пишет руду**: RLS разрешает только `SELECT` своих строк, все
  изменения — через `SECURITY DEFINER` RPC. Плагинные RPC отозваны у
  `anon`/`authenticated` и выданы только `service_role`.
- **Ограничение таблиц**: журнал — 200 строк на игрока, завершённые спуски — 20,
  выводы — 50. Старое удаляется в тех же RPC.

## Диагностика

| Симптом | Причина и решение |
|---|---|
| `/sw ping` → «SQL «Шахты» ещё не применён» | Не применён раздел 16. Запусти `scripts/apply_mc_sql.mjs`. |
| `HTTP 401/403` | Неверный `service-key` или ключ от другого проекта. |
| «Сначала привяжи аккаунт» | Нет привязки: сайт → «Шахта» → код → `/sw link КОД`. |
| «Не хватает места для N руды» | Освободи слоты; заявка останется pending и повторится. |
| Занос завис | Плагин повторяет его раз в `poll-seconds`; прогресс — в `plugins/SwinlineMine/pending.yml`. |
| После рестарта нет автовыдачи | Проверь `auto-deliver: true` и `/sw withdraw` вручную. |

`pending.yml` хранит незавершённые заносы и возвраты. Не редактируй его без
необходимости: потеря nonce может привести к повторному заносу.
