# SVINLINE

Пародийный букмекер на виртуальные SV₽. React + TypeScript + Vite + Supabase
(Auth через Twitch/GitHub, таблицы profiles / bets / events, Realtime).
Публикация — GitHub Pages.

## Команды
- `npm install` — установка
- `npm run dev` — запуск для разработки
- `npm test` — тесты игровой логики (ставки, плинко, лужи, колесо, ежедневки)
- `npm run build` — сборка в `dist/`

## Структура
- `src/App.tsx` — интерфейс: линия, купон, игры, админ-панель, синхронизация с Supabase.
- `src/data.ts` — категории, акции, новости, тексты «О компании».
- `src/logic.ts` — расчёт ставок/выплат/возвратов (чистые функции + тесты).
- `src/plinkoLogic.ts`, `src/puddlesLogic.ts`, `src/wheelLogic.ts`, `src/dailyLogic.ts` —
  математика игр: RTP всех игр 94–99%, проверяется тестами.
- `src/Plinko.tsx`, `src/MudPuddles.tsx`, `src/DailyRewards.tsx` — игровые компоненты.
- `src/supabase.ts` — клиент Supabase (URL и publishable-ключ публичны по дизайну).
- `scripts/supabase_security_setup.sql` — SQL для Supabase: RLS, guard-триггеры,
  таблица общей линии `events`, защита вставки ставок.
- `scripts/sync_users.cjs` — legacy-скрипт синхронизации реестра пользователей, больше не используется.

## Общая линия событий (чтобы события видели все игроки)

Линия синхронизируется через таблицу `events` в Supabase. По умолчанию (если SQL
не выполнен) сайт работает в локальном режиме — события видит только браузер
администратора. Чтобы включить общий режим:

1. Supabase Dashboard → SQL Editor → выполнить `scripts/supabase_security_setup.sql`
   (раздел 7; разделы 1–6 и 8 — рекомендуется вместе с ним).
2. Готово: события, созданные в админ-панели, видны всем; расчёт/отмена/закрытие
   и удаление применяются у всех игроков через Realtime, открытые ставки при
   удалении возвращаются.

## Модель безопасности (честно)

- Баланс SV₽ — клиентский: живёт в localStorage и синхронизируется с `profiles.bal`.
  Для пародийной валюты это осознанное решение; «защитить» баланс от самого игрока
  без серверного движка невозможно.
- Админ — аккаунт с ником `egor4kill`; в SQL это проверяет `is_platform_owner()`
  (плюс уникальный индекс на ник защищает от подделки).
- Действия админа по чужим профилям (начисление/блок/удаление) из браузера
  отклоняются RLS — интерфейс честно сообщает об ошибке. Для полноценной админки
  нужны серверные RPC-функции (Supabase Edge Functions).
- Ставки в БД всегда вставляются со статусом `pending` (guard-триггер), расчёт —
  только сервисной ролью.

## Как добавить событие

Войди как `egor4kill` → «+ Создать событие» в админ-панели (или быстрые шаблоны
в 1 клик). Формат события: `{id, cat, league, title, team1, team2, score, isLive,
liveTime, desc, out: [[название, коэффициент], ...]}` — см. тип `Ev` в `src/data.ts`.

## Публикация на GitHub Pages

Пуш в `main` → `.github/workflows/deploy.yml` прогонит тесты, соберёт и опубликует
сайт. Путь `base` подставляется автоматически по имени репозитория.
